# 재시작 및 Gemini 전송 복구

## 확인된 문제

- GUI 재시작 경로가 중지된 RunControl의 이벤트만 지웠다. 상태는 STOPPED여서 이후 일시정지 요청을 무시하지만 작업 체크포인트는 통과했다.
- 확장 전송 경로에 기존 Gemini 탭 활성화와 창 포커스 확보가 없었다. 기존 로그의 send_commit_unknown은 클릭 요청 뒤에도 입력창에 프롬프트가 남고 새 사용자 턴이 없는 상태였다. 백그라운드 상태가 모든 실패의 원인임을 확정한 것은 아니다.
- Gemini 실패가 SKIPPED로 반환되면 실패 집계에서 빠졌다.
- 이웃 목록의 partial 상태나 수집 완료 여부를 실행 가드가 충분히 검사하지 않았다. 페이지네이션이 없다는 사실만으로 마지막 페이지로 처리했다.
- 본문에 실제로 등장하는 일부 음식명이 사전에 없어 자연스러운 댓글이 재작성됐다.

## 변경 계약

- 기존 작업 스레드가 종료된 경우에만 새 RunControl 및 stop/pause/skip 이벤트를 생성한다. 중지된 객체는 이벤트가 잘못 지워져도 다시 실행되지 않는다.
- 기존 Gemini 탭의 URL과 창 ID를 확인한다. 최소화된 창만 복원하고 해당 탭과 창을 활성화한다. 새 프로필, 로그인, 탭은 만들지 않는다.
- 새 대화 준비 전 및 전송 직전에 활성화한다. 전송 직전 취소/만료/실행 ID를 재검사하고 MAIN world에서 숨김/포커스 상실, 입력 변경, 버튼 변경을 검사한다.
- 동일 요청의 중복 전송 메시지는 같은 Promise로 합쳐 한 번만 전송한다. 클릭 결과가 불명확해도 재클릭하지 않는다. 새 사용자 턴 및 연결된 응답 확인 계약은 유지한다.
- 활성화는 최대 2.5초를 기다린다. 실패하면 명시적 오류로 종료한다. 사용자가 직전에 창을 전환한 경우도 숨김 상태에서 전송하지 않고 오류 처리한다.
- 활성화 시간 초과 후 늦게 반환된 탭 조회는 추가 창 활성화를 시작하지 않는다. 이미 브라우저에 전달한 API 호출 자체를 취소할 수 있다고 가정하지 않는다.
- 전송 진단에 visibilityState/documentFocused를 기록한다. 클릭하지 않은 실패는 clickCount=0, 전달 결과 불명은 null로 기록한다.
- Gemini 운영 실패는 실패 집계에도 포함한다. SKIPPED와 실패 집계는 중복될 수 있으며 두 수치를 독립된 글 수로 합산하면 안 된다.
- 브리지 preflight는 읽기 전용으로 유지한다. 상태 잠금을 잡은 채 서버를 재시작하지 않으며, 포트 해제 후 복구는 기존 GUI 확장 연결 테스트 경로를 사용한다. Python 로그에서도 포커스 진단값이 유지된다.
- 이웃 목록은 complete, collection_complete, terminal 및 알려진 총수 일치를 요구한다. 목록 끝은 페이지네이션 또는 전체 개수 일치라는 근거가 있어야 한다. 미확인 이웃을 서로이웃으로 간주하지 않는다.
- 로그에서 확인한 음식명만 사전에 보강한다. 본문에 실제로 등장해야 통과한다. 기본 프롬프트는 늘리지 않고 음식 재작성 지시의 조합 강제를 제거한다.
- 본문과 초안에 공통으로 존재하는 꼬들/두툼/푸짐 감각 표현은 메뉴명을 반복하지 않아도 허용한다. 본문에 없는 향의 강도 등은 이 조건으로 통과시키지 않는다.

## 적용

1. 현재 작업을 정상 종료한다.
2. 기존 Chrome의 확장 관리에서 이 프로젝트 확장을 다시 로드한다.
3. 기존 로그인된 Gemini 탭을 새로고침한다. 로그인 프로필은 그대로 유지한다.
4. Python 앱을 다시 실행한다. 런타임 빌드가 `13.2.8-foreground-send-v1`인지 확인한다.

전송 시 Gemini 창이 앞으로 나올 수 있다. 백그라운드 전용 API 방식으로 전환한 것은 아니다. 실제 로그인된 Gemini의 전송/응답 및 Naver 서버 댓글 등록은 별도 실전 검증이 필요하다. 이번 변경만으로 실전 오류가 모두 해결됐다고 판정하지 않는다.

## 테스트 데이터 보호

두 리포트 생성 테스트는 임시 폴더에만 JSON/Markdown을 저장한다. 전체 테스트를 실행해도 저장소의 기존 리포트 네 파일을 덮어쓰지 않는다. 실행 로그와 사용자 설정은 릴리스 커밋에 포함하지 않는다.

## 검증 결과

- `python3 -m pytest -q`: 748 passed, 1 skipped, 96 subtests passed. 제외한 테스트는 없다.
- 기본 실행에서 건너뛴 GUI 검사는 `NAVER_GUI_TEST=1`로 별도 실행해 1 passed를 확인했다. 임시 설정과 모킹된 컨트롤러를 사용하며 네이버 작업은 시작하지 않았다.
- `node --test tests/test_extension_runtime_contract.mjs tests/test_extension_fake_clock.mjs`: 104 passed.
- 기존 리포트 네 파일의 전체 테스트 전후 SHA-256이 같음을 확인했다.
- 실제 Chrome의 기존 Gemini 탭에는 미전송 입력이 남아 있어 변경하지 않았다. 실제 로그인된 Gemini 전송 성공은 위 검사 결과로 대체하지 않는다.
