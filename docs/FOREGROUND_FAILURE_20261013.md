# 2026-10-13 Gemini 창 활성화 실패 점검

## 확인된 사실

- 검사 대상은 data/bot.log의 2026-10-13 07:28:33 RUN_CONFIG 이후 실행이다.
- 실행 빌드는 Python f6f3018 / 확장 13.2.8-foreground-send-v1이었다.
- 목표 댓글 60개 중 진행 로그상 15개 등록 후 멈췄다.
- 08:00:08, 08:01:02, 08:03:10의 요청이 모두 gemini_foreground_unavailable로 실패했다. 이 요청에는 SEND_DISPATCHED가 없다.
- 08:03:53에 3회 연속 실패 서킷 브레이커가 pause_requested / pause_ack를 기록했다. 프로세스 종료가 아니라 자동 일시정지다.
- 기존 코드는 Chrome API 예외를 버리고 동일 오류 문자열만 반환했다. 따라서 오늘 실패가 OS 포커스 지연인지, API 거절인지, 탭/창 소실인지 로그로 확정할 수 없다.

## 수정

- 창 활성화 후 즉시 한 번 검사하던 동작을, 기존 2.5초 제한 안에서 100ms 간격으로 상태를 확인하는 방식으로 변경했다. 재활성화나 전송 버튼 재클릭은 하지 않는다.
- 대상 탭의 창 또는 Gemini URL이 바뀌면 중단한다. 시간 초과 뒤 늦게 완료된 브라우저 호출이 후속 활성화를 시작하지 못하게 하는 기존 계약을 유지한다.
- FOREGROUND_FAILED에 요청 ID, 대상 탭 ID, 실패 단계 및 Chrome API 오류를 기록한다. API 오류 메시지는 200자로 제한하고 프롬프트/본문/계정 정보는 별도로 수집하지 않는다.
- 초기 활성화와 실제 전송 직전 활성화 실패 모두 Python 로그로 전달한다.
- 전송 확인 불명 시 재전송하지 않는 계약과 3회 연속 실패 시 일시정지는 유지한다.
- 확장 식별자를 13.2.9-focus-settle-v1로 갱신했다. 이전 확장과 새 Python의 혼용을 정상으로 간주하지 않는다.

## 검증 및 적용

- 기존 코드에서 지연 포커스 및 API 원인 보존 테스트 2개가 실패함을 확인한 뒤 수정했다.
- 관련 Python 테스트: 56 passed.
- 확장 테스트: 107 passed.
- 전체 Python 테스트와 새 빌드의 실전 전송은 이번 변경 후 실행하지 않았다.
- 기존 일시정지 앱/Chrome 로그인/사용자 설정/리포트 네 파일은 변경하지 않았다. 네이버 댓글과 공감을 실행하지 않았다.
- 적용은 기존 앱 정상 종료 → 기존 브리지 확장 새로고침 → Python 앱 재시작 순서다. Gemini에 미전송 입력이 있으면 보존하고, 새 진단 탭에서 전송을 먼저 확인한다.

포커스 지연의 재현 가능한 결함은 수정했지만, 오늘 세 실패의 직접 원인을 확정하거나 모든 재발을 방지했다고 주장하지 않는다. 다음 실패 시 FOREGROUND_FAILED의 stage/detail로 실제 API 실패를 구분해야 한다.
