# Gemini 제출 확인 보강

상태: 구현 후 검증 보류. 사용자 요청에 따라 실행/구문/브라우저 테스트를 수행하지 않았다.

## 첨부 분석에 대한 판단

비활성 버튼 강제 활성화, synthetic click와 native click 중복, click과 Enter 동시 실행, 입력창의 잔여 텍스트를 무시하는 fresh 판정은 코드에서 확인된 수정 대상이다.

다만 사용자 턴이 사라졌다는 사실은 서버 미접수의 증명이 아니다. DOM 재렌더링, 화면 이동, selector 변경 등으로도 발생한다. 따라서 자동 재전송 1회를 넣는 제안은 채택하지 않았다. 내부 framework state에 대한 추정도 확정된 원인이라고 표현하지 않는다.

## 반영 내용

- 전송 버튼의 disabled/aria-disabled 상태를 변경하지 않는다.
- 활성 버튼의 click() 1회만 사용한다. Enter fallback과 별도 synthetic click은 실행하지 않는다.
- editor의 직접 innerText/textContent 대입 fallback을 제거했다. input/textarea는 native value setter를 사용한다. 이것만으로 trusted event나 내부 상태 동기화가 보장되는 것은 아니다.
- 안정된 정확한 프롬프트 readback과 자연스럽게 활성화된 전송 버튼을 요구한다. 일정 길이만 채워져도 통과하던 readback 우회를 제거했다.
- 정확한 프롬프트와 일치하는 사용자 턴이 650ms 연속 관찰되고, composer 비움/생성 시작/응답 턴 중 하나가 확인돼야 제출 확인 상태로 진행한다. 서버 접수 증명과는 구분한다.
- 제출 확인 실패는 send_commit_unknown, 준비 실패는 send_not_ready로 구분한다. 불확실한 제출을 자동 재시도하지 않는다.
- 제출 확인 이후 사용자/응답/생성 증거가 모두 3초 이상 사라지면 send_state_lost로 종료한다. 이 역시 서버 미접수를 의미하지 않는다.
- fresh 판정에 composer 비움과 생성 비활성 조건을 포함하고, background에서 동일 instance/epoch로 650ms 간격 재확인한다.
- 실행 중 reset을 거절하고 새 대화 버튼을 실제 호출한 경우에만 epoch를 증가시킨다. reset 성공 여부는 별도 fresh 확인을 거쳐야 한다.
- SEND_DIAG 및 제출 단계 이벤트를 Python 로그에 request_id와 함께 남긴다. 프롬프트 전문은 추가 로그에 기록하지 않는다.
- 확장 버전 13.2.4, runtime build 13.2.4-send-commit으로 변경했다. 설치된 확장이나 브라우저는 이번 작업에서 재시작하지 않았다.
- disabled 우회/중복 이벤트를 요구하던 기존 단위 테스트를 새 계약에 맞게 수정하고, 단일 클릭 사례를 추가했다. 실행하지 않았다.

## 검증 재개 후 필수 항목

1. 미반영 입력 상태, disabled 버튼, 입력창 재렌더 시 실제 클릭 0회.
2. 정상 요청에서 클릭 1회, Enter 0회, 정확한 사용자 턴 상관관계 확인.
3. 일시적인 사용자 턴 출현/소멸은 제출 확정으로 취급하지 않음.
4. 지연된 서버 접수와 화면 재렌더 상황에서도 자동 재전송 없음.
5. 긴 프롬프트/접힌 사용자 턴의 정확 일치 추출을 실환경에서 확인. 필요하면 원문을 복원하는 extractor를 개선하고 임의의 새 턴을 허용하는 fallback은 복구하지 않음.
6. 새 대화 전환 지연, 이전 프롬프트 잔류, stop/cancel/이전 응답 지연 처리.
7. 이전 품질 복구 변경과 함께 전체 회귀 테스트. 기존 38개 통과 기록은 현재 코드의 검증 결과가 아님.

코드 전달과 운영 준비 완료는 다르다. 이 커밋은 검증 보류 상태로 개발 브랜치에만 전달한다.
