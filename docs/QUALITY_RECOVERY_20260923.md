# 댓글 품질 복구: 수정 내역과 남은 구현 계획

기준: HEAD 611448a와 기존 작업자의 미커밋 변경 위에 추가 수정.
상태: 추가 구현 후 사용자 요청으로 검증 보류. 아래 38개 통과 기록은 이전 수정본 결과이며 현재 수정본에는 적용되지 않는다.

## 추가 반영: 검증 보류 중

- Gemini 대기 진단에 post/navigation/tab/instance/epoch, route, document 준비 상태, 사용자/응답 노드 연결 여부를 추가하고 Python 로그에 보존한다. 타임아웃 시간이나 새 대화 제어 동작은 추측으로 변경하지 않았다.
- RunControl 인스턴스 ID와 요청/ACK/재개/중지 로그를 추가했다.
- inspector에 source/style policy를 전달한다. 설명조/습관적 마무리 등 지정된 문체 문제는 진단으로 분리하며, 사실 오류나 완전 중복 등 비권고 오류는 재작성 한도가 소진되면 실패로 종료한다.
- 완전 중복 검사를 문체 검사보다 먼저 수행한다. 문체 경고가 중복 판정을 가리지 않게 한다.
- 음식명/단어 겹침과 장소 반응만으로 재작성하거나 자동 등록을 해제하지 않는다. 사실/오염/최종 텍스트 검사는 유지한다. 이는 의미적 관련성 검증을 완성한 것은 아니다.
- 학습 기록에 schema version, origin, 본문 hash를 추가한다. origin=human_reviewed 기록만 취향 예시에 사용한다. 출처가 없는 과거 자료는 원본을 보존하고 학습 대상에서 제외한다. 따라서 재검토 전에는 개인화 예시 수가 줄어들 수 있다.
- 테스트 프로세스의 학습 기록 기본 경로를 임시 디렉터리로 분리했다. NAVER_LEARNING_DATA_DIR로 명시할 수 있다. 운영 로그 등 전체 데이터 경로 분리는 아직 별도 작업이다.
- 기존 학습 파일을 읽지 못하거나 배열 형식이 아니면 빈 자료로 덮어쓰지 않고 저장을 중단한다. 이번 작업에서 실제 코퍼스 정리/백업/삭제는 실행하지 않았다.
- 비교기에 --review-output을 추가했다. 실제 생성된 두 초안을 A/B로 섞어 원문과 함께 내보내며, 모델 대응표는 별도 원본 결과에만 보관한다. 평가 데이터 확대와 사용자 평가는 미실행이다.

이번 추가 수정 후 테스트, 구문 검사, dry-run, 브라우저 실행, 외부 생성/게시를 모두 실행하지 않았다. 커밋/푸시도 하지 않았다. 실제 검증은 사용자가 재개를 요청한 후 수행한다.

## 이번 작업에서 지킨 경계

- Antigravity 및 다른 앱을 실행하거나 조작하지 않았다.
- 기존 변경을 되돌리지 않았다. 커밋/푸시하지 않았다.
- 실제 댓글/공감, 외부 API 호출, 운영 코퍼스 변경을 하지 않았다.
- 테스트는 logger를 대체하고 dry-run 산출물을 /tmp에 저장해 운영 로그와 평가 보고서를 보존했다.
- 일반 FIFO, 서로이웃 한정 처리, 이미 공감된 4개 연속 종료, Chrome 프로필과 대기 설정을 변경하지 않았다.

## 구현 완료

### 1. 일시정지 체크포인트

`app/run_control.py`: PAUSE_REQUESTED를 PAUSED로 전환한 최초 호출만 대기하던 구조를 수정했다. 이미 PAUSED인 상태에서 들어오는 다른 호출도 재개/중지까지 기다린다.

두 스레드를 이용해 첫 번째 ACK 후 두 번째 체크포인트가 통과하던 결함을 수정 전 재현했다. 수정 후 두 호출 모두 멈춘다. 이것이 과거 UI 증상의 유일한 원인이라는 뜻은 아니다.

### 2. 본문 예산과 핵심 내용

`naver/content_extractor.py`: 긴 도입 문단이 예산을 독점하지 않도록 도입부 우선 포함을 전체 예산의 1/4 이하로 제한했다. 들어가지 않는 문단 때문에 탐색을 종료하지 않고 다음 후보를 검토한다. 0/1/3자 예산과 700자 예산도 초과하지 않는다.

한 문단 자체가 매우 긴 글은 아직 일부 잘림이 가능하다. 문장/부정/조건 단위의 보존은 후속 범위다. 이번 변경은 전체 본문 추출 방식을 교체하지 않는다.

### 3. 확인된 사실 판정 반례

`services/comments/community_rhythm.py`:

- 유료 주차라는 이유만으로 주차 가능 표현을 차단하지 않는다.
- 24시간 영업을 명시적으로 부정하는 근거를 긍정 주장의 근거로 쓰지 않는다.
- 다른 대상의 무료 서비스가 아니라 주차에 연결된 무료 근거를 요구한다.
- '무료로 리필' 표현을 검사에서 놓치지 않는다.
- '바사삭'을 '바삭'으로 옮긴 표현을 식감 날조로 처리하지 않는다.

이 검사는 제한된 규칙 기반 방어다. 범용 한국어 의미 검증을 완성했다고 주장하지 않는다. 질문, 조건부 주차 지원, 여러 가게 비교, 복합 부정, 임의의 동의어에는 추가 평가가 필요하다.

### 4. 생성 지침과 비교기의 정직성

`services/ai_prompt.py`: 정보만 되풀이하지 않고 느낌/반응을 자기 말로 쓰도록 지시했다. 부정 후기나 힘든 이야기에는 억지 긍정을 붙이지 않도록 했다. 자유로운 감상/기대/비유와 사실 날조 금지 원칙은 유지했다.

`scripts/compare_prompts.py`:

- inspector와 final gate에 같은 본문, preset, source, style policy를 전달한다.
- 생성 프롬프트에도 동일 preset을 명시한다.
- 더 짧다는 이유로 승자를 정하지 않는다. 생성된 쌍은 human_review_required다.
- dry-run은 생성 실패/동점/통과율 0%가 아니라 not_run, not_evaluated, null 통과 집계다.
- 실제 API 호출은 모델을 명시해야 한다. API 결과는 프로덕션 웹 실행 검증과 구분한다.
- 기존 API 방식은 선택적 비교 경로로만 남겼다. 공급자 SDK/실제 모델의 동작은 이번에 검증하지 않았다.

구버전 프롬프트 형식 테스트 두 개는 v3.0을 명시하도록 변경했다. 기본 프롬프트 테스트는 v3.2의 실제 요구를 검사한다.

## 검증 결과

- 신규 회귀 테스트 14개: 수정 전 잘못된 동작을 재현한 사례 포함.
- 신규/기존 관련 테스트 총 38개 통과.
- 수정한 실행 모듈 5개 AST 파싱 통과.
- 비교기 4개 예제 dry-run 완료. 결과: `/tmp/naver-quality-recovery-dry-run.json`.
- 전체 저장소 테스트, 실모델 생성, 브라우저 등록, 사용자 선호도 평가는 미실행.

## 다음 구현 순서

1. **Gemini 웹 실패 재현**: request_id, tab/instance/epoch, route, 사용자 턴 확인 및 사라짐, response binding을 동일 실행에서 수집한다. 새 대화 전환/selector 문제/외부 탐색을 구분한 뒤 해당 원인만 수정한다. 타임아웃 연장부터 하지 않는다.
2. **제어 상태 실환경 검사**: 수동 pause, 자동 3회 실패 pause, skip, stop 각각에서 ACK 이후 신규 공감/댓글/스크롤/생성 요청이 없는지 확인한다. 실행 코드 버전도 함께 기록한다.
3. **검증기 정책 정리**: 사실 위반과 스타일 감점을 분리한다. 메뉴 단어 미등장만으로 fail-closed하거나 표현 허용 목록만 늘리지 않는다. 현재 앵커 재작성 경로를 포함해 생성/재작성/접미사/등록 전 검사 조건을 한 번에 대조한다.
4. **취향 데이터 정제**: 테스트/자동 등록/직접 수정 출처를 분리한다. 기존 코퍼스는 백업 후 의심 자료를 격리한다. 사용자 확인 없이 좋은 예시라고 확정하지 않는다.
5. **실제 품질 평가**: 서로 다른 분위기의 글 30개에 기존/개선 댓글을 생성해 순서를 가리고 비교한다. 가짜 체험/사실 왜곡 0건, 사용자 선호 21/30 이상을 초기 목표로 삼는다. 자료는 취향 예시와 평가용으로 분리한다.

완료 보고는 코드 수정, 오프라인 검증, 실제 웹 실행, 사용자 만족도를 각각 별도로 표시한다. 현재 완료된 것은 앞의 두 항목 중 이번 수정 범위뿐이다.
