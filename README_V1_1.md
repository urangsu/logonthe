# Naver Blog Assistant V1.1

기존 Python 앱을 유지하면서 수동 댓글 보조, 근거 중심 반응분석, 선택적 Google Workspace 동기화를 추가한 버전입니다.

**상태: 구현 및 로컬 검증 진행 버전. 실사용 승인 완료가 아닙니다.**

- 네이버 실제 로그인 및 관리 화면의 일부 구조를 읽기 확인했습니다. 추가 확인은 다른 프로세스의 프로필 점유로 중단했습니다.
- 새글소식 ON/OFF 의미와 반응 목록의 실제 끝까지 수집은 아직 승인되지 않았습니다. 해당 기능은 `확인 불가`/`partial`로 남습니다.
- Google OAuth 클라이언트와 실제 계정 승인이 아직 없습니다. 실제 파일 생성·업로드·시트 읽기 검증은 수행하지 않았습니다.
- 테스트의 Chromium 페이지는 격리된 HTML fixture입니다. 실제 네이버·Google 성공의 증거가 아닙니다.

## 실행

1. 처음 한 번 `Naver Blog Assistant Setup.command`를 더블클릭합니다.
2. 이후에는 `Naver Blog Assistant.command`를 더블클릭합니다. 실행할 때 패키지를 재설치하지 않습니다.
3. `설정`에서 내 블로그 ID를 확인합니다.
4. `글 탐색 → 네이버 로그인`에서 직접 로그인합니다. 기존 로그인 프로필은 그대로 사용합니다.

명령 실행도 유지합니다.

```bash
cd /Volumes/무제/jusik/naver-blog-bot
.venv/bin/python main.py
# 시스템 Python에 의존성이 설치되어 있다면 기존 python3 main.py도 가능
```

외장 볼륨이 연결되어 있어야 합니다. 실행기를 다른 폴더에 복사해도 기본 프로젝트 경로를 확인합니다. 프로필 사용 중이면 기존 작업이 끝날 때까지 기다립니다. 잠금을 강제로 지우거나 사용자 브라우저를 강제 종료하지 않습니다.

## 화면

| 화면 | 할 일 |
|---|---|
| 글 탐색 | 소스 선택, 로그인, 수동 댓글 보조 패널 실행 |
| 반응분석 | 최근 공개 글 5·10·20개 선택, 저장 상태 및 이웃 검색 |
| Workspace | Google 계정 승인, 비공개 폴더 열기, 전송·재시도·연결 해제 |
| 설정 | 블로그 ID, 탐색 범위, URL, 검색어, 발췌 범위, 선택 꼬리말 |

기존 상세 설정은 파일에 보존합니다. 기본은 수동 보조 모드이며, 설정에서 `기존 자동화 모드`를 명시적으로 켜면 기존 Gemini 웹 자동화와 지연 설정을 사용합니다.

## 댓글 보조

네이버 페이지에 Python이 패널을 붙입니다. 확장프로그램이나 Tampermonkey 설치는 필요 없습니다.

`ChatGPT 열기`는 자동화 브라우저가 아닌 macOS 기본 브라우저에서 실행합니다. Google이 Playwright 브라우저 로그인을 차단하는 문제를 피하기 위한 동작입니다.

`기존 자동화 모드`를 선택하면 Gemini 웹 자동화 경로를 사용할 수 있습니다. 본문은 네이버 모바일·구형 iframe·PC 레이아웃 후보를 자동 탐색하고, 전용 본문 영역이 없을 때 표시된 본문을 보조 후보로 사용합니다. 설정 화면에서 행동 간 대기, 다음 글 대기, 랜덤 휴지 확률과 범위를 조정할 수 있습니다.

```text
제목·본문 확인 → GPT 프롬프트 복사 → ChatGPT 열기
→ 답변 붙여넣기·수정 → 문장 검사 → 댓글창에 넣기
→ 네이버에서 직접 등록 → 등록 관찰 → 명시적으로 다음 글
```

- 자동 추출 결과가 부족할 때만 본문 보완 입력을 제공합니다. 제목만으로 생성하는 프롬프트는 만들지 않습니다.
- 본문은 지시문이 아닌 인용 데이터입니다. 보지 못한 사진, 방문·구매·체험을 만들어내지 않게 안내합니다.
- NFC 정규화 후 공백과 선택 꼬리말 포함 12~100자입니다. 조용히 삭제하거나 잘라내지 않습니다.
- 입력란 덮어쓰기는 확인하며, 입력 상태가 확인 이후 달라져도 삽입을 막습니다.
- 프로그램은 등록 버튼을 누르거나 Enter로 제출하지 않습니다. 한글 조합 중 Enter도 등록 동작으로 해석하지 않습니다.
- `입력됨`, `등록 확인됨`, `등록 확인 불가`, `건너뜀`을 구분합니다. 입력란이 비었다는 이유로 성공 처리하지 않습니다.
- 게시글이 바뀌면 이전 명령은 무효입니다. 새 페이지에 이전 답변을 넣지 않습니다.
- 공감은 패널의 명시적 요청과 확실한 미공감 상태가 모두 있을 때만 한 번 처리합니다. 불명확하면 네이버에서 직접 확인합니다.
- 초안은 `data/helper_drafts/`에 글별로 보존합니다. 네이버 입력란에서 수정한 내용도 별도로 복원할 수 있습니다. 저장 오류가 나면 직접 복사하세요.

## 반응분석의 해석

| 지표 | 단위와 범위 |
|---|---|
| 공감한 글 수 | 해당 이웃의 공감이 확인된 서로 다른 대상 글 |
| 댓글 단 글 수 | 해당 이웃의 댓글이 확인된 서로 다른 대상 글 |
| 총댓글 수 | 귀속을 확인한 댓글 항목; 본인 댓글 제외 |
| 반응한 글 수 | 공감 또는 댓글을 확인한 글의 합집합 |
| 내 새글보기 | 내 계정 설정만 의미. 상대방의 설정·푸시 알림과 다름 |

부분 수집의 횟수는 확인된 하한입니다. 미발견은 `0`이나 무반응이 아니라 `확인 불가`입니다. 명부가 불완전하면 참여자를 비이웃으로 확정하지 않고 관계 미확인 목록에 남깁니다.

신규 유예는 한국 날짜 기준 추가일과 이후 2일입니다. 정확한 48시간 유예라는 뜻이 아닙니다. 미반응 검토는 추가일 이후 게시되었고 발행 후 48시간이 지났으며 완전히 수집한 글이 최소 3개일 때만 가능합니다. 날짜 불명확·명부 누락·목록 중간 실패·페이지 제한·취소는 판정 보류 사유입니다.

반응으로 방문·열람 여부나 상대방의 관심을 추정하지 않습니다. 관계 점수, 자동 이웃 삭제, 자동 설정 변경은 없습니다.

## Workspace 연결

앱의 OAuth는 Codex의 Google Drive 연결과 별개입니다.

1. Google Cloud 프로젝트에서 Drive API, Sheets API, Docs API를 활성화합니다.
2. OAuth 동의 화면을 구성하고 필요한 경우 본인 계정을 테스트 사용자로 추가합니다.
3. **Desktop app** OAuth 클라이언트를 만들고 JSON을 다운로드합니다. 저장소에 커밋하지 않습니다.
4. 앱에서 `Workspace → Google 계정 연결`을 눌러 JSON을 선택합니다.
5. 시스템 브라우저의 계정 승인을 마친 뒤 앱에서 계정·폴더·전송 항목을 확인합니다.
6. 자동 동기화 여부를 선택합니다. 거절하면 토큰을 저장하거나 분석 파일을 전송하지 않습니다.

요청 권한은 `drive.file` 하나입니다. 토큰은 macOS Keychain에 저장하며 평문 파일 저장으로 우회하지 않습니다. 로컬 콜백과 PKCE를 사용합니다.

```text
Naver Blog Workspace/                새 비공개 내 드라이브 폴더
├─ 이웃 관계 대시보드                 Google Sheets
├─ 운영 가이드 및 업그레이드 계획      Google Docs
├─ 분석 기록/                        허용 필드만 담은 실행별 JSON
└─ 기존 자료 - 검증 전/               계정 귀속을 확인한 과거 자료
```

시트 탭: 대시보드 / 이웃별 현황 / 글별 반응 / 비이웃 반응 / 분석 이력 / 데이터 품질 / 사용자 메모.

전송: 블로그 ID·닉네임·블로그명·링크·관계·그룹·추가일·반응 집계·내 새글보기·관측 시각·정형 진단 코드.

전송하지 않음: 댓글 원문·초안·쿠키·로그인 정보·클립보드·임의 오류 응답·네이버 HTML. 기존 자료의 원본 전체도 그대로 업로드하지 않고 허용 필드만 내보냅니다. 귀속 블로그가 없는 과거 CSV는 자동으로 계정을 추정하지 않습니다.

## 동기화와 보존

- SQLite 저장 성공 후 별도 작업자가 업로드합니다. Drive 장애가 로컬 작업을 막지 않습니다.
- 실행 ID·계정·해시로 중복을 막습니다. 생성 응답이 유실되면 원격 앱 식별자를 조회합니다. 확인할 수 없는 생성은 중복 생성 대신 `creation_outcome_unknown`으로 보류합니다.
- 확정적인 권한 거절과 응답 유실을 구분합니다. 인증을 복구한 뒤 확정 거절 요청은 다시 시도할 수 있습니다.
- 시트 관리 탭은 하나의 batchUpdate로 적용하고 실행 ID·행 수와 실제 셀 값을 다시 읽어 확인합니다.
- 닉네임이나 제목이 `=`로 시작해도 수식으로 실행하지 않습니다.
- 오래된 실행이 최신 대시보드를 덮지 않습니다. 비교는 같은 계정·글 목록·정책·대상 집합의 검증된 실행에서만 합니다.
- 사용자의 메모, 추가 탭, 공유 권한은 수정하지 않습니다. 기존 운영 문서의 표·이미지·추가 탭도 사용자 편집으로 취급합니다.
- 파일 소유권·폴더 위치·공유 상태가 달라지면 임의로 복구하지 않고 중단합니다.
- 연결 해제는 대기 중 전송을 중단하고 Keychain 토큰을 지웁니다. 이미 전송 중이던 요청은 서버에 도달했을 수 있습니다. 원격 파일을 삭제하지 않습니다.
- 앱을 닫은 동안 동작하는 스케줄러는 설치하지 않습니다. 재실행 시 미완료 대기열을 확인합니다.

## 로컬 저장과 복구

`data/audit.sqlite3`가 분석 원본과 동기화 대기열입니다. CSV/JSON은 `data/audit_exports/<run_id>/`의 내보내기 파일입니다. 같은 날 다시 분석해도 별도 실행으로 남습니다.

기존 `data/my_blog_engagement_audit.json`과 CSV는 읽기만 하고 `legacy_unverified`로 가져옵니다. 메뉴 주소는 참가자에서 분리하며, 알려진 테스트 형태는 의심 표시를 붙입니다. 원본은 삭제하지 않습니다. 일부 오류를 제거했다고 나머지를 검증된 결과로 승격하지 않습니다.

설정은 읽기만 해서는 변경하지 않습니다. 저장 시 원본 해시 백업을 `config_backups/`에 남기고 다른 프로세스 변경이 있으면 저장을 중단합니다. 손상된 설정을 조용히 기본값으로 초기화하지 않습니다. 댓글 이력과 브라우저 프로필은 별도로 보존합니다.

## 개선 우선순위와 출시 조건

1. **실제 수집 계약 확정:** 실제 관리 화면·공감 목록·댓글/답글 목록·0건·로그인 만료·목록 마지막 페이지를 표본 대조합니다. 확인된 DOM 계약에만 capability를 부여합니다. 지금의 미검증 상태를 강제로 complete로 바꾸지 않습니다.
2. **수동 보조 실사용 QA:** 기존 입력, 한글 조합, 브라우저 뒤로/새로고침, 등록 직후 이동, 댓글 차단 글, 중단·재실행을 실제 로그인 환경에서 확인합니다. 테스트용 게시글에서 사용자가 등록을 직접 수행합니다.
3. **Google 실제 검증:** 비공개 권한·셀 일치·메모 보존·재연결·오프라인 복구·중복 없는 기록을 실제 계정으로 확인합니다.
4. **운영 품질 개선:** 모호한 “실패” 대신 수집 단계별 재확인 항목을 보여줍니다. 글 목록과 관측 시각이 바뀌면 전회 대비 비교를 제한합니다. 충분한 데이터가 쌓인 뒤에만 유용한 변화 표시를 추가합니다.
5. **선택 API 단계:** 별도 활성화·키·한도 설정과 요청 근거 표시가 준비된 뒤 공식 API를 연결합니다. 이번 버전에는 자동 생성 API를 호출하는 경로가 없습니다.

판정의 목표는 이웃을 평가하는 것이 아니라 **확인해야 할 작업을 줄이는 것**입니다. “반응은 있지만 내 새글보기 OFF”, “신규 유예”, “목록 수집 실패”처럼 관측 근거가 있는 제안만 제공합니다.

## 검증 방법

```bash
.venv/bin/python -m unittest discover -s tests -v
PYTHONPATH=. .venv/bin/python tests/ui_smoke.py
git diff --check
```

Chromium 테스트는 브라우저 실행 권한이 필요합니다. `ui_smoke.py`는 임시 설정·DB만 사용하고 실제 서비스에 연결하지 않습니다. 상세 실환경 체크리스트는 `docs/LIVE_QA_V1_1.md`를 참고하세요.

공식 근거: [Google Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [Drive 권한](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [Sheets batchUpdate](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate), [네이버 새글소식 설명](https://help.naver.com/service/5593/contents/803?lang=ko&osType=MOBILE).
