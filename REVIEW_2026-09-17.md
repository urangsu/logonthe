## Remaining findings

1. High: ui/main_window.py, _load_reply_threads worker: reply_session/reply_page are retained across calls, but each call starts a different threading.Thread. Synchronous Playwright objects must stay on their owning thread. _on_close also stops the session from the UI thread. A dedicated browser worker with queued commands and owner-thread cleanup is needed before calling repeated reply collection reliable.
2. High: ui/main_window.py, _insert_reply_to_browser: uses current_controller.session.page instead of the retained reply_page and runs browser calls on the UI thread. It does not establish that the active post matches the selected reply post. This can fail or target the wrong page. Route insertion through the reply browser owner and verify post and parent comment before filling.
3. Medium: batch/single reply generation workers do not restore disabled controls in a finally path. Unexpected service errors can leave the UI unavailable. Multiple single-generation requests can also race control re-enablement.
4. Medium: Python tests write synthetic submissions to the real user_learning_corpus.json unless its module path is redirected. The initial suite exposed this behavior; the repeated suite uses a temporary corpus copy. Raw corpus counts must not be represented as genuine user-comment counts.

## Gemini notebook proposal

The provided notebook could not be inspected through the web reader. No notebook was created and no corpus was uploaded.

Official feature reference: https://support.google.com/gemini/answer/16972047

Recommendation: use a notebook for curated style references, not as the sole factual context. Keep three separate sources: approved style examples, writing rules, and prohibited/negative examples. Exclude synthetic test records, unreviewed auto-generated submissions, duplicates, nicknames, account identifiers and URLs from style examples. Supply the current post body separately for each draft; old examples must never become facts about the current post.

The existing UserLearningService already filters and selects examples. At inspection time its cleaned set contained 51 entries; quality and provenance still require review, not merely a count check.

Integration blocker: browser_extension/background.js resets the target tab to https://gemini.google.com/app before generation. content.js also recognizes ordinary new-chat controls. Merely configuring a notebook URL will therefore not preserve notebook context. A notebook-specific conversation adapter must verify notebook identity, source readiness, fresh request/response correlation and retained context. Compare approved drafts from the current example-selection path and the notebook path on the same posts before switching.
